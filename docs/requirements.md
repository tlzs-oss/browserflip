# 要件定義

BrowserFlip — "One Click. Your Browser." の MVP(0.1.0)要件と、v0.2(デスクトップ機能、[6 章](#6-v02-要件デスクトップ機能))の要件です。設計は [architecture.md](architecture.md)、検証方法は [testing.md](testing.md) を参照してください。

## 1. 目的とスコープ

Windows(v0.2.0 のサポート対象は Windows 11)で、インストール済みブラウザーの中から既定ブラウザーを「ワンクリックで Windows の正規の設定画面へ到達して」切り替えられるようにする。既定の変更そのものは Windows の設定画面でユーザーが確定し、BrowserFlip は Windows の確認を省略・偽装しない。

対象 OS(設計上の目標): Windows 10 バージョン 1809(ビルド 17763)以降 / Windows 11。アーキテクチャ: x64 / Arm64。

**v0.2.0 で動作を確認し、サポートするのは Windows 11(x64)のみです。** Windows 10 は未検証で動作保証対象外、Arm64 版はビルドのみ確認しています(実機では未検証)。

## 2. 機能要件(MVP)

### F01 ブラウザー自動検出

HKCU と HKLM(64 ビット / 32 ビット ビュー)の `Software\Clients\StartMenuInternet` と `Software\RegisteredApplications` から、インストール済みブラウザーを検出する。

受け入れ基準:

- [ ] 実行ファイル パスをハードコードせず、レジストリの登録情報のみで検出する。
- [ ] `Capabilities\URLAssociations` に `http` または `https` を宣言するキーのみをブラウザーとして扱う。
- [ ] HKCU の登録は同名の HKLM の登録より優先される。
- [ ] 表示名は既定値 → `Capabilities\ApplicationName` → `LocalizedString` の順で取得し、`@` 形式の間接文字列は解決する。取得できなければキー名を使う。
- [ ] `RegisteredApplications` との対応付け(Capabilities パス一致、なければ名前一致)を行い、ディープリンク用の名前とスコープを保持する。
- [ ] 表示名順(大文字小文字を区別しない)に並べる。
- 範囲外(MVP): `registeredAUMID` で登録されるパッケージ版(MSIX / Store)ブラウザーの検出は Phase 2 で対応予定。

### F02 カード一覧 UI

受け入れ基準:

- [ ] 2 列のカードで、アイコン・名前・「現在の既定」バッジを表示する。
- [ ] カード全体がクリック可能で、キーボード(Tab / Enter / Space)でも操作できる。
- [ ] Windows のアプリ テーマ(ライト / ダーク)に追従する。
- [ ] Per-Monitor V2 高 DPI に対応し、モニター間移動や拡大率 100%〜200% でぼやけ・レイアウト崩れがない。
- [ ] UI 言語は English / 日本語 / 简体中文。OS の言語から自動選択し、実行中に切り替えられる。

### F03 Windows 設定を開く

受け入れ基準:

- [ ] ディープリンク対応の Windows 11(21H2: 10.0.22000.1817 以上、22H2: 10.0.22621.1555 以上、23H2 以降。いずれも 2023 年 4 月の累積更新プログラムで対応、[Microsoft Learn](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-default-apps-settings) 参照)かつ `RegisteredApplications` 登録がある場合、`ms-settings:defaultapps?registeredAppUser=<名前>` または `registeredAppMachine=<名前>` を開く。
- [ ] それ以外、またはディープリンクの起動に失敗した場合は `ms-settings:defaultapps` にフォールバックする。
- [ ] 既定の確定はユーザーが設定画面の「既定値に設定」で行う。Windows の確認を省略しない。
- [ ] `ms-settings:` 以外の URI は起動しない。

### F04 現在の既定の取得と変更監視

受け入れ基準:

- [ ] `AssocQueryStringW(ASSOCF_IS_PROTOCOL, ASSOCSTR_PROGID)` で `http` / `https` の現在のハンドラーを取得する。
- [ ] 起動時、設定を開く前、変更待機中(約 1.5 秒間隔のポーリング、最大 3 分)、ウィンドウ再アクティブ化時に再取得する。
- [ ] 変更結果を `AppliedToTarget` / `PartiallyApplied` / `ChangedToOther` / `NoChange` として判定し、UI に反映する。
- [ ] `http` と `https` のハンドラーが異なる場合は不一致警告を表示する。
- [ ] 検出済みブラウザー以外が既定の場合も、その旨(未認識)を表示する。

### F05 エラー処理

| ケース | 期待動作 | 受け入れ基準 |
| --- | --- | --- |
| ブラウザーがアンインストール済み(exe なし) | カードを無効表示 | [ ] クリックしても設定を開かず、理由を表示する |
| 登録が不完全(URL 関連付けなし / `RegisteredApplications` なし) | 前者は一覧から除外、後者はトップページへフォールバック | [ ] クラッシュせず、可能な範囲で操作を継続できる |
| 設定画面を開けない | エラー メッセージ | [ ] シェル起動の失敗を例外で落とさずメッセージ表示する |
| グループ ポリシー `NoControlPanel` / `SettingsPageVisibility` で `defaultapps` が非表示 | ブロック メッセージ | [ ] 設定を起動せず、管理者のポリシーによる旨を表示する |
| グループ ポリシー `DefaultAssociationsConfiguration` | 警告 | [ ] サインイン時に変更が元に戻る可能性がある旨を表示する |
| ユーザーがキャンセル | 情報メッセージ | [ ] 戻った時点で変更がなければ「変更されませんでした」を表示する |

## 3. 非機能要件

| 区分 | 要件 |
| --- | --- |
| 権限 | 管理者権限を要求しない(`asInvoker`)。 |
| 安全性 | レジストリは読み取り専用。`UserChoice` / `UserChoiceLatest` への書き込み、UserChoice ハッシュの計算・偽造、DISM の既定関連付け XML の使用を禁止する。 |
| 依存関係 | 本体にサードパーティの実行時依存を持たない。テスト用パッケージはライセンス許可リストで監査する。 |
| プライバシー | テレメトリなし、ネットワーク アクセスなし。 |
| 多言語 | 英語・日本語・簡体字中国語。すべてのリソース キーが 3 言語に存在すること(単体テストで強制)。 |
| 表示 | Per-Monitor V2 高 DPI、ダークモード。 |
| アクセシビリティ | キーボードのみで全操作が可能。すべての操作要素に `AutomationProperties.Name` を設定し、スクリーン リーダーで読み上げられる。 |
| 品質 | ビルド警告をエラー扱い(`TreatWarningsAsErrors`)、`dotnet format` 準拠、Core の単体テストが CI で成功する。 |
| 性能 | 起動から一覧表示まで体感的に即時(目安 1 秒以内)。ポーリングは待機中のみ行う。 |

## 5. MVP 完了条件

- [ ] Windows 11 実機で起動する。
- [ ] インストール済みブラウザーを検出して表示する。
- [ ] 現在の既定ブラウザーを表示する。
- [ ] カードから Windows 設定の該当ページを開ける。
- [ ] 設定で変更後、BrowserFlip に戻ると表示が更新される。
- [ ] `http` / `https` の不一致を検出して警告する。
- [ ] 管理者権限なしで動作する。
- [ ] 単体テストが成功し、コード レビューが完了している。
- [ ] 依存関係のライセンス監査が完了している。
- [ ] [testing.md](testing.md) の実機受け入れテストに合格している。

## 6. v0.2 要件(デスクトップ機能)

状態: **実装済み(v0.2.0)**。要件の詳細と計画は [backlog.md](backlog.md)、設計は [desktop-design.ja.md](desktop-design.ja.md)、操作方法は [user-guide.ja.md](user-guide.ja.md) を参照してください。v0.1 の F01〜F05 の動作は変更しません。

| ID | 要件 | 主な仕様 |
| --- | --- | --- |
| V2-01 | 専用アプリアイコン | オリジナル図案(既存ブラウザーのロゴに似せない)、SVG マスター・PNG 16〜512 px・多解像度 ICO。EXE・ウィンドウ・タスクバー・通知領域に適用。MIT |
| V2-02 | 常に手前に表示 | 通常画面・コンパクトバーのピン ボタンとメニューで切り替え、保存。全画面アプリ / プレゼンテーション中は一時解除 |
| V2-03 | コンパクトバー | 横(高さ 44 / 52 DIP)/ 縦(幅 48 / 56 DIP)。既定ブラウザーを強調、ツールチップ、通常画面に戻る・表示オプション ボタン、多数のブラウザーはスクロール |
| V2-04 | 画面端ドッキング | 左 / 右 / 上 / 下、作業領域の内側に 4 DIP の余白。ドラッグ終了時に端から 24 DIP 以内ならスナップ。AppBar 登録はしない |
| V2-05 | 自動的に隠す | ドッキング中のみ。離脱 600 ms 後に収納し 8 × 56 DIP のタブを残す。タブ上 150 ms 滞在 / クリック / Enter / トレイで展開 |
| V2-06 | 通知領域アイコン | 既定で有効。左クリックで表示、右クリックでメニュー。「ウィンドウを閉じても通知領域で動作を継続」は既定 OFF。Explorer 再起動後に再登録 |
| V2-07 | 設定の永続化 | `settings.json` に表示設定を保存。フィールド単位の検証とフォールバック、アトミック保存、v0.1 互換、`--settings <パス>` で別ファイル |
| V2-08 | 複数モニター・DPI | Per-Monitor V2。物理ピクセルでの配置、DPI をまたぐ移動、ディスプレイ構成変更・スリープ復帰・タスクバー変更後の再配置、画面外からの復旧 |

### 非機能要件(v0.2 追加分)

| 区分 | 要件 |
| --- | --- |
| 常駐負荷 | グローバル フックを使わない。カーソルのポーリング(100 ms)はコンパクト + ドッキング + 自動的に隠す が有効な間のみ、全画面確認(1 秒)は最前面表示が ON の間のみ |
| 安定性 | 配置とイベント処理が相互に再帰しない(再入ガード、確認は最大 3 回、通知のデバウンス) |
| 安全性 | v0.1 と同じ(レジストリ書き込みなし、管理者権限不要、ネットワーク通信なし)。書き込むファイルは設定ファイルのみ |
| 操作性 | Windows の設定画面での操作をバーが妨げない(設定画面を開いた後も自動的に隠す機能は通常どおり収納する) |
| アクセシビリティ | コンパクトバー・タブ・メニューをキーボードで操作でき、`AutomationProperties.Name` を設定する |
| 多言語 | 追加した文言はすべて 3 言語で提供する(単体テストで強制) |

### 受け入れ条件(要約)

- [ ] 最前面表示が再起動後も維持され、全画面アプリ実行中は前面に割り込まない。
- [ ] コンパクトバーからブラウザーを選ぶと、v0.1 と同じ設定画面遷移と状態更新が行われる(回帰なし)。
- [ ] 左右ドッキングは縦、上下ドッキングは横になり、各モニターの作業領域内に収まる。ドラッグで端に近づけるとスナップする。
- [ ] 自動的に隠すで収納時はタブのみが表示され、タブ・トレイから復帰できる。抑止条件中は収納しない。設定画面の操作を妨げない。
- [ ] モニターの接続・切断、解像度 / 拡大率変更、スリープ復帰、タスクバー位置変更の後も画面内に再配置され、保存位置が画面外なら補正される。
- [ ] 通知領域アイコンの左クリック・右クリック メニューで全操作ができ、Explorer 再起動後も再表示される。トレイ無効でも全機能が使える。
- [ ] 設定が保存・復元され、v0.1 の設定ファイルを読み込め、不正な値はその項目だけ既定値に戻る。
- [ ] 拡大率 100% / 125% / 150% / 200%、拡大率の異なる 2 モニター環境で表示が崩れない。
- [ ] 終了時に通知領域アイコンと関連リソースが解放される。

検証手順は [testing.md](testing.md) の「v0.2」節を参照してください。完全な受け入れ条件は [backlog.md](backlog.md#4-受入条件) にあります。
